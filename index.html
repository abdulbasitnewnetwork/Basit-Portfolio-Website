Networking Labs & Study Topics

📍 IPv4 Addressing

Understanding IP address classes, address ranges, and host/network calculations for efficient network planning.

Learn More

IPv4 addressing uses 32-bit addresses divided into classes (A, B, C, D, E). Key concepts include dotted decimal notation (192.168.1.1), unicast, broadcast, and multicast addresses.

📊 Subnetting

Dividing networks into smaller subnets using subnet masks, enabling better address utilization and network segmentation.

Learn More

Subnetting allows dividing a large network into smaller logical networks. Uses CIDR notation (e.g., /24) and subnet masks to define network and host portions of an IP address.

🔗 VLANs (Virtual LANs)

Creating separate logical networks on a single physical switch, improving security and network organization.

Learn More

VLANs separate users into different broadcast domains without physical separation. Tagged frames carry VLAN IDs, allowing switches to forward traffic appropriately.

🔀 Switching

Understanding switch operation, MAC address tables, port learning, and frame forwarding mechanisms.

Learn More

Switches operate at Layer 2 (Data Link). They learn MAC addresses from incoming frames, build MAC tables, and forward frames to appropriate ports based on destination MAC addresses.

🛣️ Routing

Learning how routers forward packets between different networks using routing tables and routing protocols.

Learn More

Routers operate at Layer 3 (Network). They use routing tables to decide where to forward packets. Static routing specifies routes manually; dynamic routing uses protocols like RIP, OSPF, or BGP.

📡 TCP and UDP

Transport layer protocols: TCP (connection-oriented, reliable) vs UDP (connectionless, fast).

Learn More

TCP ensures reliable delivery through sequencing and acknowledgments; used for web, email, file transfer. UDP is faster, connectionless; used for streaming, gaming, DNS.

🌐 DNS (Domain Name System)

Understanding DNS hierarchy, name resolution, and how domain names map to IP addresses.

Learn More

DNS translates domain names (example.com) to IP addresses. Uses hierarchical system with root nameservers, TLD servers, and authoritative nameservers for efficient lookup.

📌 DHCP (Dynamic Host Configuration)

Automatic IP address assignment to devices on a network, simplifying network management.

Learn More

DHCP automates IP configuration. Clients send DISCOVER, server responds with OFFER, client sends REQUEST, server sends ACK with IP lease details (address, gateway, DNS, lease time).

🏗️ OSI Model

Seven-layer model: Physical, Data Link, Network, Transport, Session, Presentation, Application.

Learn More

OSI model provides framework for understanding network protocols. Each layer has specific functions; data is encapsulated at each layer (PDU). Helps troubleshoot network issues.

🔗 TCP/IP Model

Four-layer model (Link, Internet, Transport, Application) - the practical model used on the internet.

Learn More

TCP/IP model is simpler than OSI, with 4 layers. Combines equivalent OSI layers. Focuses on practical internet protocols like IP, TCP, UDP, HTTP, SMTP.

📦 Encapsulation & Decapsulation

Process of adding headers/trailers at each layer (PDU formation) and removing them at the destination.

Learn More

Data flows down the stack, each layer adds its own header/trailer (encapsulation). At destination, headers are stripped away layer by layer (decapsulation) until application receives data.

🔌 Ethernet Frames

Understanding Ethernet frame structure, MAC addresses, and frame types used in LANs.

Learn More

Ethernet frame includes destination/source MAC, type field, payload data, and FCS. Switches examine Destination MAC to forward frames. Uses 48-bit MAC addresses (e.g., 00:1A:2B:3C:4D:5E).

🖥️ Cisco Packet Tracer

Hands-on network simulation tool for designing, testing, and troubleshooting networks.

Learn More

Cisco Packet Tracer simulates routers, switches, PCs, and other devices. Allows configuration of real Cisco IOS commands, testing connectivity, and observing packet flow through the network.

🔧 Network Troubleshooting

Systematic approach to identifying and resolving network connectivity and performance issues.

Learn More

Troubleshooting uses tools like ping, tracert, ipconfig/ifconfig, and analysis of logs. Follows OSI model from physical to application layer to isolate problems systematically.

Case Study: Secure Multi-Corporate Network

Designing a structured, segmented, and security-focused corporate network for multiple departments

Overview

This project focuses on designing a comprehensive network architecture for a corporate environment with multiple departments. The network is structured to provide department separation, centralized management, and security controls while maintaining inter-department connectivity where needed.

Project Type: Network Design & Simulation
Current Status: In Progress
Tool: Cisco Packet Tracer
Departments: 5 (Finance, Trading, Management, Administration, IT)

Problem Statement

Multi-department corporate environments face several networking challenges:

  • Lack of logical network separation between departments
  • Difficulty controlling and restricting access to resources
  • Inefficient IP address management and utilization
  • Increased complexity in network troubleshooting
  • Need for centralized management and consistent policies
  • Security vulnerabilities from flat network architecture

Research & Technical Requirements

The network design addresses the following requirements:

Department Connectivity

Enable each department to access necessary shared resources and services

Network Segmentation

Isolate departments using VLANs and separate IP subnets

IP Addressing Plan

Implement efficient IPv4 addressing with proper subnetting

Routing & Communication

Enable controlled inter-VLAN routing with security controls

Server Access

Centralized server placement with controlled department access

Security Controls

Implement ACLs and network security best practices

Automated Configuration

Use DHCP and DNS for simplified device management

Troubleshooting

Clear network documentation and testing procedures

Network Architecture

The network follows a hierarchical three-tier model with Internet/WAN connectivity:

Internet/WAN: External connectivity point
Router: Manages WAN connectivity and external traffic
Core Switch: Central switching fabric connecting all departments and servers
Access Switches: Department-level switches for connecting end devices
Servers: Centralized on core infrastructure for all-department access
VLANs: Logical separation of departments with controlled communication

Security Design

The network implements multiple layers of security:

  • VLAN Isolation: Departments cannot directly communicate; all inter-department traffic must pass through the router
  • Access Control Lists: Router ACLs enforce least-privilege access between departments
  • Centralized Authentication: Servers provide controlled resource access with proper credential validation
  • Network Segmentation: Sensitive departments (Finance, Administration) can be further isolated
  • Administrative Access: Device management restricted to IT department personnel
  • Monitoring: Network traffic analysis to detect unauthorized access attempts
